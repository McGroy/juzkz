# juz.kz · ortajuz.kz

Два сайта одной команды. Общая дизайн-система, разное позиционирование.

| | **JUZ** — juz.kz | **ORTA JUZ** — ortajuz.kz |
|---|---|---|
| Роль | Проектный бренд | Сервисный бренд |
| Продаёт | Разработку ПО, полный цикл | Сопровождение ИС по SLA, эксплуатацию |
| Акцент | Сине-циановый, «инженерия» | Золотой, «системы в строю» |
| Главная конверсия | Заявка на дискавери | Заявка на аудит |

Обе услуги — разработка, сопровождение и аналитика — представлены на обоих
сайтах, но с разным приоритетом: у JUZ первой идёт разработка, у ORTA JUZ —
сопровождение.

---

## Что это технически

Чистый HTML, CSS и JavaScript. **Никакой сборки.** Папку сайта можно просто
залить на хостинг — она заработает как есть. Ни Node, ни npm, ни зависимостей.

```
sites/juz/        ← содержимое juz.kz
sites/ortajuz/    ← содержимое ortajuz.kz
shared/           ← источник правды для общих файлов
tools/            ← служебные скрипты (не нужны для работы сайтов)
```

Каждая папка в `sites/` самодостаточна. Общие файлы (дизайн-система,
интерактив, движок переводов) физически лежат в обеих — так сайты не зависят
друг от друга на разных доменах. Чтобы они не разъезжались, источник правды
один — `shared/`:

```bash
./tools/sync-shared.sh    # разложить shared/ по обоим сайтам
```

**Правьте в `shared/`, а не в копиях внутри `sites/`.** Копии перезаписываются.

Файлы, у каждого сайта свои и синхронизацией не затрагиваемые:
`assets/css/theme.css`, `assets/js/config.js`, `assets/js/i18n-brand.js`,
`assets/js/i18n-<страница>.js`.

## Локальный просмотр

```bash
python3 -m http.server 8000 --directory sites/juz
# и в другом терминале
python3 -m http.server 8001 --directory sites/ortajuz
```

Открыть `http://localhost:8000`. Можно и просто открыть `index.html` двойным
кликом — всё работает, кроме относительных путей в некоторых браузерах,
поэтому лучше через сервер.

Проверка целостности перед публикацией:

```bash
python3 tools/check.py
```

Проверяет битые ссылки, несуществующие якоря, подключение скриптов
и расхождение копий с `shared/`.

## Публикация

### Обычный хостинг / nginx

Содержимое `sites/juz/` → корень juz.kz, `sites/ortajuz/` → корень ortajuz.kz.
Больше ничего не требуется.

Минимальный конфиг nginx:

```nginx
server {
    server_name juz.kz www.juz.kz;
    root /var/www/juz;
    index index.html;

    error_page 404 /404.html;

    # Статика кешируется надолго, HTML — нет
    location ~* \.(css|js|svg|woff2?|png|jpg)$ {
        expires 30d;
        add_header Cache-Control "public";
    }
    location / {
        try_files $uri $uri/ =404;
    }
}
```

### GitHub Pages

Один репозиторий обслуживает один домен, поэтому для двух сайтов нужны
две ветки или два репозитория. Содержимое `sites/<сайт>/` кладётся в корень
публикуемой ветки, домен указывается файлом `CNAME`.

### После публикации

- Проверьте, что HTTPS работает и HTTP редиректит на него.
- Проверьте `https://juz.kz/robots.txt` и `/sitemap.xml`.
- Добавьте сайты в Google Search Console и Яндекс.Вебмастер.

## Правка контактов

**Все контакты задаются в одном файле** — `sites/<сайт>/assets/js/config.js`.
Телефон, почта, адрес, мессенджеры и реквизиты подставляются оттуда во все
места на всех страницах. В HTML их править не нужно.

```js
window.SITE = {

  email:    "info@juz.kz",
  address:  "г. Астана, ...",
  whatsapp: "https://wa.me/77000000000",
  telegram: "https://t.me/juzkz",
  ...
};
```

Перед публикацией пройдитесь по **[CONTENT-CHECKLIST.md](CONTENT-CHECKLIST.md)** —

## Форма заявки

По умолчанию `formEndpoint` в `config.js` пустой, и форма открывает почтовый
клиент посетителя с уже составленным письмом. Это работает без сервера, но
теряет часть заявок: не у всех настроен почтовый клиент.

Чтобы заявки приходили надёжно, укажите адрес, принимающий `POST`
с `multipart/form-data`:

```js
formEndpoint: "https://formspree.io/f/XXXXXXX"
```

Подойдёт любой сервис такого рода (Formspree, Getform, Web3Forms) или
собственный скрипт на вашем хостинге. Форма сама покажет результат
и очистится при успехе.

## Языки

Русский, казахский, английский. Переключение мгновенное, без перезагрузки,
выбор запоминается в браузере и сохраняется при переходах между страницами.

**Русский — базовый язык:** он записан прямо в HTML. Переводы подставляются
поверх него только при выборе другого языка. Поэтому русскую версию правят
в самом HTML, а не в словаре.

Словари складываются из трёх слоёв, каждый следующий перекрывает предыдущий:

| Файл | Что содержит |
|---|---|
| `assets/js/i18n-common.js` | Общее для обоих сайтов: меню, подвал, форма |
| `assets/js/i18n-brand.js` | Своё для бренда: подпись логотипа, текст в подвале |
| `assets/js/i18n-<страница>.js` | Тексты конкретной страницы |

### Как перевести новый текст

1. В HTML повесьте на элемент атрибут с ключом:
   ```html
   <h2 data-i18n="services.title">Услуги</h2>
   ```
   Для строк с разметкой внутри — `data-i18n-html`, для атрибутов вроде
   `placeholder` — `data-i18n-attr="placeholder:form.namePh"`.

2. Добавьте ключ в словарь страницы в разделы `kk` и `en`. Русский не нужен —
   он уже в HTML.

Принудительно открыть страницу на нужном языке: `?lang=kk`, `?lang=en`.

### Автоопределение языка

По умолчанию выключено: сайт всегда открывается на русском, если посетитель
не выбрал другой язык. Для рынка Казахстана это предсказуемее, чем язык
браузера. Включается в `config.js`: `autoDetectLang: true`.

### Что стоит знать про SEO

Переводы применяются в браузере, поэтому поисковые роботы индексируют русскую
версию. Для основной аудитории этого достаточно. Если понадобится вывести в
поиск казахскую или английскую версию, нужно будет отдавать их отдельными
страницами (`/kk/`, `/en/`) — это единственное место, где сайтам понадобится
шаг сборки.

## Дизайн-система

`shared/css/core.css` — вся система в одном файле, разбитом на
пронумерованные разделы: токены, раскладка, типографика, кнопки, карточки,
формы, шапка, подвал и так далее.

Цвета, отступы, скругления и тайминги заданы CSS-переменными в `:root`.
Брендовые цвета переопределяются в `assets/css/theme.css` каждого сайта —
это единственное место, где задаётся акцентный цвет.

```css
/* sites/juz/assets/css/theme.css */
:root {
  --accent: #4f7cff;     /* основной акцент */
  --accent-2: #22d3ee;   /* вторичный, для градиентов и мелких деталей */
}
```

Смена акцентного цвета сайта — это правка двух строк.

Шрифты: Inter и JetBrains Mono с Google Fonts, оба с полным кириллическим
набором, включая казахские буквы (ә, ғ, қ, ң, ө, ұ, ү, һ, і).

Логотип подключается картинкой — `<img class="logo__img" src="assets/img/logo.svg">`.
Высота задаётся в CSS (`.logo__img`), ширина считается автоматически,
поэтому пропорции знака не искажаются ни при какой вёрстке.

### Доступность и производительность

- Анимации отключаются при `prefers-reduced-motion`.
- Контент виден без JavaScript: блоки скрываются только когда скрипт
  подтверждённо работает.
- Семантическая разметка, состояния фокуса, `aria`-атрибуты у меню,
  табов и аккордеона, ссылка «к основному содержанию».
- Анимация фона в герое останавливается, когда герой уходит с экрана.
- Никаких внешних библиотек: только шрифты с CDN.
